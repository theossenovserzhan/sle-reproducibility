\section{Evidence and Version Boundaries}
The original submission and first revision batch are frozen. The new executable is \path{revision_v2/mpc/msle_system.mpc}; its independent oracle is \path{reference.py}. Every run records the SHA-256 of the circuit, parameters, backend configuration and input artifact. Only measurements matching the final source hashes enter the revised performance tables. Warmups, diagnostic runs, earlier source versions and legacy circuits remain in the logs but are not pooled with final timed runs.

An audit found that the legacy integrated program sampled five positive 30-bit key contributions and added them. The sum has at most $\log_2(5(2^{30}-1)+1)\simeq32.32$ bits of support, not 128 bits. The legacy circuit also used 73 MiMC-style rounds and an implicit-field/bounded-output-decomposition configuration. Its timings cannot establish the cost of the corrected cryptographic configuration. We replace them with a known-prime implementation, independent uniform full-field contributions, 81-round permutations and canonical 128-bit output decomposition. The old program is preserved for audit, not silently relabeled as secure evidence.

The internal SLE predecessor is unpublished. Frozen source \texttt{sle\_sort\_merge\_transition.mpc}, the earlier integrated circuit and their configuration files identify its provenance. The revised sort/merge comparator is newly adapted to the same complete masked-state contract, field width, capacity and verification as the direct transition. It is not an unrelated old timing point.

\section{Concrete Cryptography and Independent Tests}
\path{parameters.json} contains the decimal prime, all 81 constants, generation domain and assumptions for the MiMC construction~\cite{albrecht2016mimc}. The script \path{init_parameters.py} verifies primality and $\gcd(3,p-1)=1$. Keys are sampled with operating-system randomness using rejection-based \path{secrets.randbelow(p)} for each party and each of nine keys. Summing modulo $p$ is uniform if at least one contribution is independent and uniform. The passive model does not require malicious input-validation machinery.

The locator key is independent of eight mask-word keys. For each mask word, apply its MiMC permutation to the locator, decompose the field element canonically into 128 bits, and retain bits 0--63. All eight words are concatenated in the released bit order. No additive offset is used as an unproven domain separator between keyed calls. The independent oracle implements both encryption and inversion and generates full-field vectors including $0$, $p-1$, $2^{64}$ and $2^{127}$.

The secure primitive test checks 16 values and 1024 selected mask bits, exact full-field equality, row-association preservation under secret shuffle and the shuffled multiset. Separate reference unit tests verify permutation inversion, key-support configuration and exact re-keying scores. Passing these tests establishes implementation agreement, not a cryptanalytic proof of MiMC.

The SHAKE-256 lifecycle simulator is separate: its domain is \texttt{M-SLE/root-mask/v1}, followed by the key bytes and an eight-byte big-endian simulation locator. These historical simulation locators are 64 bits. Corrected MPC locators are uniform field elements near 128 bits. Attack diagnostics from the simulator are labeled as such and never used to infer MPC performance or exposed-key security.

\section{Persistent State and Access Schedule}
For $N$ records, $d=512$, block width $w=4$, and capacity $C=\min(N,8+\lceil N/4\rceil)$, there are $M=(d/w)2^wC$ padded slots. The logical state per party contains
\[
S=N(d+3)+2M+9
\]
field shares: locator, label, tie tag and $d$ protected bits per database row; locator and validity per slot; nine keys. Its nominal 128-bit payload is $16S$ bytes per party. MP-SPDZ serialization, object overhead and communication buffers are additional. The shared-root baseline has one key and $S-8$ fields.

Database rows are shuffled as complete bundles of $d+3$ fields. Labels and tie tags therefore do not remain in public row order. The index retains a public physical bucket/slot schedule, but locator and validity contents remain secret-shared. Every lookup scans every slot and uses secret flags. No queried bucket, number of candidates or fallback bit is opened. The deliberate price is scanning and comparing the entire padded index. This is a concrete access-hiding reference backend, not an implementation of Path ORAM or a sublinear search claim.

After a transition, every field is refreshed by adding independently input zero sharings from all five parties. The represented value remains unchanged. We rely on the passive Shamir input/refresh protocol; functional refresh tests do not establish a composable mobile-security guarantee. Secure erasure and the corruption-period definition remain external assumptions.

The persisted-state family reads each server's own share file at fixed public offsets. An external trusted initialization fixture samples two full-field coefficients per state field and sends $f(j)$ only to server $j$, $j=1,\ldots,5$. MPC privately inputs these values and interpolates with weights $(5,-10,10,-5,1)$. The client checks this reconstruction for every field before installation. Thus a computing party is given one Shamir evaluation, rather than the plaintext database or bucket contents. The fixture knows the public research roots and initial keys and is outside the corruption model. It is a test initializer, not a deployed capture application. Each later re-key receives only new key contributions and refresh inputs; queries receive a probe and threshold. Old keys, templates, locators, validity bits, labels and tie tags come from the persisted share bundle.

The input-inclusive reference initializes invocations independently; the persisted-state family instead performs successive transitions and reload queries on the same logical store. The two families are not pooled. A source audit verifies identical cryptographic helpers and protocol tails; their state entry points differ. Tests cover exact/reject decisions, private indexed retrieval, and an omitted candidate entry followed by rollback and a separate reload query. MP-SPDZ signals a successful read ending exactly at EOF with $-1$; short reads raise an I/O error. The adapter distinguishes these conditions.

The write instruction stores one logical selected-state bundle. Filesystem crash recovery, distributed publication and operating-system secure erasure are outside the implementation; local audit files are not a mobile-secure production store. A rejected relation retains old decoded values and keys even if maintenance changes shares or physical row order. Accordingly, rollback tests assert semantic state equality, not byte equality of files.

\section{Retained and Reproduced Lifecycle Diagnostics}
The released 128-identity CelebA simulation uses 20 epochs and seed 20260818. Each mask key is 32 bytes. Initial locators are sampled without replacement from $1,\ldots,2^{31}-1$ and serialized in eight bytes. Subsequent simulation locators are 64-bit keyed BLAKE2b tokens with an explicit collision check. This hash-based token surrogate is not a proof or implementation of a permutation on all 64-bit inputs. Corrected MPC uses the actual full-field permutation described above.

At every adjacent-epoch transition, direct-linkage AUC compares 128 mated negative-Hamming scores with $128\cdot127$ non-mated scores. Hungarian assignment minimizes the complete old/new Hamming cost after randomizing observed new-row order. The relational attack excludes the self-distance, sorts the remaining 127 within-epoch distances for each row, forms the mean absolute difference between every old/new signature pair, and applies the same assignment algorithm. A single global epoch XOR mask is the relational positive control. Stable templates give the direct-linkage positive control; supplying the correct key and locator recovers the root exactly. None of these controls uses the corrected MPC timings.

A fixed random 75/25 identity split gives 96 training and 32 test rows for a multi-output ridge attack. Inputs are protected bits with a bias coordinate, outputs are root bits, ridge parameter is 10, and predictions are thresholded at 0.5. The comparison predicts every bit from its training-set majority. The observed attack/prior accuracies, 0.5242/0.5627, concern this attack family and auxiliary-information setting only. Per-epoch means and the original descriptive normal intervals are preserved; they are not uncertainty over new biometric populations.

The separate refresh demonstration uses toy field $65537$ on 65536 bit positions. Three same-epoch shares reconstruct, while three shares drawn from different refreshed sharings coincide at one position. This is a functional illustration, not a 128-bit cryptographic benchmark or a mobile-adversary proof. The actual corrected MPC refresh uses the main field and the entire state bundle.

The revision reruns the released simulation with one resource-only correction: integer-population sampling replaces a materialized 16-GiB integer range. The sampled indices and RNG state are unchanged. Original and corrected source, expected aggregates and the reproduced per-epoch outputs remain in the artifact. This avoids making ordinary reproduction depend on a machine with more than 16 GiB available RAM.

\section{Retrieval, Capacity and Integrity}
For each block $g$, form secret one-hot flags for the query's $w$-bit value. Multiply each slot validity by its bucket flag. For every database row, compare its locator with every slot using full-field equality; OR the flagged matches to deduplicate. Calculate exhaustive and candidate-restricted winners with the same secret stable tie tags. If not all records were retrieved and the candidate winner's distance is at least $d/w$, privately select the exhaustive winner. All scores and both selection paths are computed on a public schedule.

Enrollment counts are checked before executing a benchmark. If any bucket exceeds $C$, the run rejects enrollment and requires a new public capacity configuration. CPU diagnostic tables also show unbounded candidate unions and deliberately insufficient capacities, explicitly flagged. Such rows are not results from silently truncated secure searches. The eight-bit capacity policy is $\min(N,8+\lceil4N/2^8\rceil)$ and often fails at larger $N$; its unbounded candidate recall is diagnostic only.

Expected relation tuples are derived from the \emph{proposed} decoded templates. In addition, every proposed template is compared with the old protected template XOR the old and new masks. The relation acceptance bit is the product of template binding, locator-translation success and two independent multiset checks. This correction binds both old/new roots and new root/index membership. Invalid slots contribute the multiplicative identity. Two independently sampled full-field challenge triples follow candidate fixation.

Fault cases are: one missing valid occurrence; duplicate occurrence; move to the wrong bucket; corrupt a locator; use a wrong index-transition key; retain one old locator; flip one protected-template bit; retain one old protected template. For each case the diagnostic circuit verifies rejection, old-state retention and a subsequent valid query. Accept/reject controls use threshold zero with an exact enrolled root and a distinct probe. These checks are application integrity tests within passive MPC.

\section{Biometric Selection and Calibration}
The submitted CelebA NPZ remains byte-identical (SHA-256 \texttt{96862a03...486f0db1}). Source images are recovered from the public \texttt{flwrlabs/celeba} dataset pinned to revision \texttt{2d738f56e0e7f925ea36ae7c808ea925264aacec}. A range reader downloads only the identity columns of 19 Parquet shards; row indices identify the first six train images for the same 128 evaluation identities. Image bytes and shapes are checksummed. Recovered floats are compared with the fixed gallery/probe root bits and with all historical split metrics. Any mismatch is reported explicitly and the new float/binary pair remains valid only for its reconstructed image protocol.

The main fixed CelebA cohort and the historical portability cohort are distinct. The latter samples 128 of the available train identities with at least six images using seed 20260722; only one identity overlaps the fixed cohort. We therefore reconstruct its original images independently before comparing the 20 historical ranks. A direct comparison of new splits on the fixed cohort with the old portability scores is retained as an audit of this population distinction, not interpreted as failed algebraic reproduction. The first six original Parquet image rows per identity are used; unavailable thumbnail URLs are not substituted with resized images.

LFW extraction uses the complete funneled archive, not an incomplete extraction directory or stale joblib cache. There are 13233 JPEGs and 5749 identities; 311 have at least six images. The old 192-identity manifest supplies 128 evaluation, 32 pilot calibration and 32 pilot unknown identities. The 20 split seeds are \texttt{20260722+20000+split}; two of six images form a gallery mean and the remaining four are probes. The reconstructed binary Rank-1 and Rank-5 equal every historical LFW split exactly.

The additional manifest freezes seed 20261030 before extracting 5557 new identities. The first 512 permuted identities calibrate; the next 512 are unknown tests; the rest are distractors. A random image is chosen using this same frozen generator, without quality or recognition filtering. All new cohorts exclude the original 192 identities. The same crop and model preprocessing are applied to every cohort: LFW crop $(78,70,172,195)$, $94\times125$ intermediate image, $160\times160$ FaceNet input, RGB normalization $(x-0.5)/0.5$, VGGFace2 pretrained InceptionResnetV1, normalized output embeddings. Complete image IDs and versions are in the manifests. These choices reproduce the historical pipeline; no claim is made that this is an optimal modern face frontend.

At each gallery size, unknown scores are the maximum cosine similarity or negative Hamming distance over the same gallery used for enrolled tests. Sort 512 calibration maxima in ascending order. With allowed count $k$, choose the next representable number strictly above the $(k+1)$th highest score. Accept when score is at least threshold. This handles tied binary scores conservatively. The empirical rule uses $k=5$; the conservative rule uses the largest $k$ with
\[
\Pr\{\operatorname{Binom}(512,0.01)\le k\}\le0.05,
\]
which is $k=1$. This is an order-statistic statement under IID identity-score sampling, not a bound under population shift. The unknown test cohort is never used for threshold selection.

Verification-pair pilot rows additionally compare four probes per enrolled identity with every gallery prototype, giving one genuine and $N-1$ impostor pairs per probe. Their thresholds use a separate 32-identity calibration gallery. Pair counts do not imply pair independence. The main revised rejection evidence instead uses independent unknown identities and identity-level intervals. The earlier frequent-identity pilot (at least six source images per identity, six probes each) is retained as a harder, distinct population. It must not be pooled with the new single-image unknown cohort to imply a stable low FPIR.

\section{Secure Measurement and Cost Model}
All five party processes share one WSL host, over loopback. The frozen MP-SPDZ~\cite{keller2020mpspdz} source revision begins \texttt{9d809599}; its full 40-character commit is recorded in the artifact. Ubuntu uses g++ 13.3.0. The host is Windows 11 Home Single Language 10.0.26200, Intel i5-1135G7, four cores/eight threads, 21154324480 bytes RAM; WSL is limited to about 9.6 GiB RAM and 3 GiB swap. Build and runtime logs retain exact commands. The compiler receives \texttt{-P p -b 64 -M}; the circuit sets statistical security 80, bit length 64 for bounded scores/group identifiers, and explicitly 128 for field output decomposition and sorting. \texttt{-b 64} is the compiler optimization budget, not the field size. Locator permutation, relation-factor and state-selection vectors are batched at 4096; canonical mask decomposition uses batches of 64 records. The compiler memory budget is 512, and radix sorting uses one worker thread. Public runtime loops bound compiler expansion without changing key separation or field arithmetic. Earlier unrolled-mask and unbounded-broadcast versions hit compiler limits at $N=128$ and $N=256$ respectively; their outputs are preserved and excluded from final performance results.

Every performance point has a warmup followed by three recorded repetitions with fresh keys and varying probe rows. Oracle inputs and diagnostic comparisons are disabled in timed circuits; the public result is checked against the external oracle where a query is present. Compile time is logged separately. Total VM time includes input and maintenance, and wall time also includes launcher overhead. Each timer's communication is party-zero traffic; \emph{global} traffic is a separate total from MP-SPDZ and is never mislabeled as a phase total. RSS from \texttt{/usr/bin/time -v} is the largest child's peak, not aggregate five-party memory.

The optimized sort/merge baseline first stably compacts the $M$ padded rows by their secret validity bit using a one-bit oblivious radix sort. The known valid count is $L=N(d/w)$; a private check verifies that the first $L$ rows are valid and the remaining rows are invalid. Only the $N+L$ database and valid-index rows are then sorted by all 128 canonical old-locator bits. Stable order puts database source rows before index rows within an equal-key group. Full-field adjacent equality produces bounded group IDs; segmented doubling propagates the new source locator. Perfect-permutation reveal-sort operations restore join positions and then all original padded slots; they do not open the hidden locator ordering. Invalid slots receive fresh field values. This avoids both sorting every dummy slot at full field width and overflowing the field with a packed 129-bit key. All template masking, verification, logical selection, shuffle and refresh match the direct transition, as verified by a source audit. Insufficient capacity aborts both equally. The interrupted all-padding-sort warmup has no completed timing result and is excluded.

The held-out cost model and communication projections use only the input-inclusive reference family. They do not predict persisted-file loading cost. The two families have the same computation after loading, but their initialization and I/O paths differ; their latency observations are therefore reported separately.
